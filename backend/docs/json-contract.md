# Формат ответов модели (строгий JSON)

На JSON-ответе модели держатся все проверки агента. Если поле названо иначе или у него другой тип,
критики либо не увидят ошибку, либо забракуют верный ответ. Поэтому формат фиксированный:
**промпты можно менять как угодно, формат — только вместе с `graph.py` и `critics.py` (и тестами).**

## Ответ агента (роль `answer`)

```json
{
  "status": "ответ",
  "answer": "18000",
  "quote": "что составляет 18 000,00 рублей",
  "file": "01_izveshchenie.txt",
  "evidence": [
    {"file": "01_izveshchenie.txt", "quote": "что составляет 18 000,00 рублей", "value": "18000", "part": 1}
  ],
  "calc": null
}
```

| Поле | Тип | Обязательно | Правила |
|---|---|---|---|
| `status` | строка | да | ровно одно из: `ответ`, `расхождение`, `нет в документах`, `не знаю` (регистр не важен) |
| `answer` | строка | для `ответ`/`расхождение` | числа цифрами без пробелов (`18000`); даты `27.11.2026 10:00`; да/нет — `да`/`нет`; при расхождении оба значения: `60 и 75` |
| `quote` | строка | для `ответ`/`расхождение` | **дословный** фрагмент одного документа, ≥ 8 символов, содержит значение из `answer` |
| `file` | строка | желательно | имя файла с цитатой (если ошибся — код поправит по месту цитаты) |
| `evidence` | массив объектов | желательно | все места, где упоминается параметр, включая изменения извещения. Поля `file`, `quote`, `value` — строки; `part` — номер части вопроса (для вопроса из нескольких частей), иначе `1` |
| `calc` | строка или `null` | для вопросов-расчётов | арифметика из чисел документа: `"1800000 * 5 / 100"`. Только числа, `+ - * /`, скобки |

### Что проверяет код

- `quote` ищется в документах так же, как это делает `check.py`: без учёта регистра, лишних пробелов, вида кавычек и `ё`/`е`.
  Почти дословная цитата (≥ 90% совпадения) подтягивается к точному тексту.
- Каждое число из `answer` должно быть в `quote` или рядом с ней в документе.
- `calc` вычисляет код. Операнды должны быть в документах и не взяты из старой редакции. Результат подставляется в `answer`.
- По `evidence` критики находят расхождения (только внутри одной `part`) и цитаты из старой редакции.
  В вопросе из нескольких частей число из `answer` может подтверждаться цитатой любой части (опция `multipart`). Без `evidence` пропущенное расхождение
  по срокам ещё ловит `crosscheck`, а по остальным параметрам — уже нет.

## Ответ критика-модели (роль `critic`)

```json
{"ok": false, "problem": "в цитате срок в рабочих днях, а в ответе — календарные"}
```

`ok` — boolean, `problem` — строка (обязательна при `ok: false`).
Если критик вернул не JSON, ответ **не** бракуется: он уже прошёл проверки кодом.

## Что будет при нарушении формата

| Нарушение | Что происходит |
|---|---|
| не JSON / JSON обёрнут в ` ```json ` / текст вокруг / `<think>…</think>` | обёртку и рассуждения срезает `llm.parse_json`; если JSON не найден — повтор с замечанием `[format]` |
| неизвестный `status` | повтор с замечанием `[format]` |
| числа вместо строк (`"answer": 12`), `null`, мусор в `evidence` | приводится к строкам, мусор отбрасывается — не ошибка |
| попытки (`max_attempts`, по умолчанию 3) кончились, а ошибки остались | итог «не знаю» (0 баллов вместо минуса за обман) |

Baseline («было») формат не проверяет: если модель ответила текстом, этот текст и сдаётся. В этом и смысл «как есть».

## JSON-режим API

В профиле модели `json_mode: true` (по умолчанию). Тогда в запрос уходит `response_format: {"type": "json_object"}`,
и API само гарантирует валидный JSON-объект. Если API этот параметр не поддерживает и падает с 400, выключите `json_mode`
в профиле (`PATCH /api/models/{id}`): `parse_json` справится и без него.

Схему полей `response_format` не задаёт, она задаётся промптом (`prompts.py`) и проверяется кодом.

## Как менять формат

1. Поменять промпт в `app/pipeline/agent/prompts.py`.
2. Поменять разбор в `graph.py` (`answer`, `_evidence`) и `Draft` в `critics.py`.
3. Обновить тесты в `tests/test_agent.py` и этот документ.
4. Прогнать `pytest` и прогон на примере. Сравнивать с предыдущим прогоном на **той же** модели.
