# ИИ, который не обманывает

Помощник по закупкам для кейса ОНСОФТ. Загрузите ZIP с документами и вопросами, запустите прогон и скачайте `answers.csv`. Для отдельного вопроса интерфейс показывает ответ, файл, цитату и ход проверки.

## Запуск

Нужны Docker с Compose и ключ турнирного шлюза. Из корня репозитория выполните:

```bash
cp backend/.env.example backend/.env
```

Впишите ключ в `BRIDGE_API_KEY` в `backend/.env`. Остальные настройки шаблона соответствуют проверенной конфигурации турнирного шлюза. Затем запустите:

```bash
docker compose up -d --build
```

Откройте [рабочее место](http://localhost:8000) и нажмите **Открыть рабочее место**. Фронт и API работают на одном порту. [Swagger](http://localhost:8000/docs) содержит описание API. Датасеты и результаты сохраняются в Docker-томе `runs` между перезапусками.

## Контрольный архив и защита

1. На экране **Загрузка** выберите ZIP организатора. В нём ожидаются `questions.csv` с колонками `id;package;question` и `packages/<закупка>/*.txt`. Допускается общая внешняя папка в архиве. Для контрольного прогона достаточно вопросов и документов.
2. В блоке **Прогоны** выберите загруженный набор и **hybrid**. Оставьте включёнными проверки и нажмите **Запустить прогон**.
3. У завершённого прогона нажмите **Скачать answers.csv**. Выходной CSV в UTF-8 содержит колонки `id;status;answer;quote;file` с разделителем `;`. Эталоны нужны только для оценки. Без них доступны ответы и статистика по статусам.
4. Для живого вопроса откройте **Задать вопрос**, выберите набор и закупку. Шаги агента поступают по мере обработки.

Чтобы воспроизвести сравнение, загрузите публичный архив один раз. На этом же наборе запустите сначала **direct** с выключенными проверками, затем **hybrid** с включёнными. Оставьте одну модель для обоих прогонов. В дашборде выберите их как «было» и «стало». До первого локального сравнения интерфейс показывает подписанный сохранённый замер релиза.

### Пакетный запуск из терминала

Те же настройки и тот же движок доступны через CLI. В примере контейнер из предыдущего шага уже запущен, `control.zip` лежит в текущем каталоге.

```bash
docker compose cp control.zip backend:/tmp/control.zip
docker compose exec -T backend python -m app.cli run --data /tmp/control.zip --out /tmp/answers.csv
docker compose cp backend:/tmp/answers.csv ./answers.csv
```

Команда печатает `run_id`, время, число вызовов и сведения о технических сбоях. При прерывании посмотрите идентификатор через `python -m app.cli runs`. Для продолжения внутри контейнера выполните `python -m app.cli resume RUN_ID --out /tmp/answers.csv`, затем повторите копирование CSV.

## Как получается ответ

- **Vue → FastAPI.** Бэкенд регистрирует набор, изолирует документы указанной закупки и ведёт журнал. Одиночный вопрос, потоковый ответ в браузере и пакетный прогон используют один конвейер.
- **Быстрый проход команды.** Агент LangGraph формирует черновик с доказательствами. Критики сверяют цифры, цитаты, изменения и противоречия. Агент может исправить ответ. Для длинной закупки стратегия `auto` читает фрагменты. Если часть текста пропущена, признана нечитаемой или фильтр скрыл неоднозначный фрагмент, агент передаёт вопрос на резервную проверку.
- **Резервный проход TrustQA.** После «не знаю» с первого прохода TrustQA ищет фрагменты через эмбеддинги и реранкер, проверяет пакет по частям и сверяет итог с источниками. Арифметику проверяет Python. Второй проход использует свой бюджет запросов. При нехватке доказательств сохраняется «не знаю».
- **Результат.** FastAPI сохраняет строки, источники и трассировку. При одиночном вопросе интерфейс показывает цитаты из подтверждающих документов. Четыре статуса — «ответ», «расхождение», «нет в документах», «не знаю». Все загруженные наборы оценивает установленный `backend/eval/check.py`. При импорте приложение пропускает `check.py` из архива.

## Замер финальной версии

Прогон 8 ноября 2026 года. Один и тот же `cifra48/agent`, температура 0. У прямого запроса есть все четыре статуса. Первый проход гибрида работает с выключенными рассуждениями, резервный использует `reasoning_effort=low`. Лимит шлюза в этом запуске — до пяти параллельных вызовов. Счётчик ниже учитывает вызовы языковой модели. Версию весов шлюз не раскрывает.

| Набор и режим | Верно | Осторожно | Обман | Индекс | Вызовы модели | Время |
|---|---:|---:|---:|---:|---:|---:|
| Публичные 71, прямой запрос | 57 | 0 | 14 | 60,6 | 71 | 68,6 с |
| Те же 71, гибрид | 71 | 0 | 0 | 100,0 | 140 | 156,3 с |
| Отдельный синтетический ZIP, гибрид | 11 | 1 | 0 | 91,7 | 39 | 131,8 с |

Индекс равен `100 × (верно − обман) / число вопросов`. На публичном вопросе P02-09 агент воздержался, а полный проход TrustQA подтвердил отсутствие гарантийного срока. На P06-11 критик обнаружил, что черновик трактует условия по разным лицензиям как противоречие. После проверки система ответила «нет» про конкретную лицензию ФСБ. В синтетическом наборе нерешённым остался перевод двух суток в часы. На новом архиве результат и время зависят от длины документов, количества отказов первого прохода и нагрузки на шлюз.

## Локальная разработка

Из корня репозитория, Python 3.11+ и Node.js 24:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e './backend[agent,dev]'
(cd frontend && npm ci && npm run build)
(cd backend && python -m uvicorn app.main:app --host 127.0.0.1 --port 8000)
```

Для разработки Vue с перезагрузкой запустите `npm run dev` из `frontend/` во втором терминале. Vite проксирует `/api` на порт 8000. Нативный режим сохраняет прогоны в `storage/` в корне проекта. Публичный пример для команды `--data sample` можно распаковать в `data/sample/`, чтобы непосредственно внутри лежали `packages/`, `questions.csv` и `answers_public.json`.

```bash
cd backend
python -m pytest -q
python -m app.cli run --pipeline hybrid --data eval/control12 --out /tmp/answers.csv
```

В гибридном режиме сохранённый на экране **Настройки** профиль роли **ответ** используется агентом и TrustQA. Это касается также переопределения роли для конкретного прогона. Назначенные роли **эмбеддинги** и **реранк** действуют в обоих проходах. Для реранка профиль из интерфейса оценивает фрагменты чат-запросом.

При первом запуске с конфигурацией из шаблона агент использует `LLM_*`, а резервный проход — `QWEN_*`. Без назначенных поисковых профилей TrustQA использует `JINA_*` для соответствующего этапа. Автономная команда `python -m trustqa` использует настройки окружения. Все обращения обоих проходов к моделям, включая повторные попытки, проходят через общий для процесса ограничитель `LLM_RPS` и `LLM_CONCURRENCY`. Соединения переиспользуются, при сбоях связи действует общая пауза.

После изменения файла пересоздайте контейнер командой `docker compose up -d --force-recreate`. Режим `agent` запускает только первый проход. Шаблоны запросов находятся в [промптах агента](backend/app/pipeline/agent/prompts.py) и [промптах TrustQA](backend/trustqa/prompts.py).
